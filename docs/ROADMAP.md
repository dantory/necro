# necro — 서 있는 할 일 목록

**이 파일이 「다음에 할 일」의 유일한 출처다.** 세션 기억에 두면 세션과 함께 죽는다.
상시 감시 크론(necro-work)이 30분마다 이걸 읽고 맨 위 항목을 하나씩 끝낸다.
비어 있으면 **아무 말도 하지 않고** 물러난다.

한 항목을 「끝냈다」고 말할 수 있는 조건 — 넷 다 되어야 한다:
검증(`node tools/cdp_verify.mjs <out.png> ui`) · 커밋 · 푸시 · 여기 체크.

- [x] **소환수가 층을 따라 안 큰다 — 깊은 층에서 네크로멘서가 혼자 싸운다** (2026-08-12)
      25분 굴려 재 보니 11분부터 20분까지 **열 번 연속 군세 1/7** 이었다. 해골 체력이
      26(트리를 다 찍어도 42) **고정**인데 층 피해는 층마다 15.5%씩 오른다 —
      20층이면 **한 대에 죽는다**(맞고 버티는 횟수 5층 6.0 → 15층 1.4 → 20층 0.7).
      「직접 안 싸운다」가 전제인 게임에서 깊은 층이 통째로 다른 게임이 되어 있었다.
      → **시체가 제 격을 기억하고 일어난 놈이 물려받는다**(RAISE_HP 0.42 · RAISE_DMG
        0.05, core.js). 층으로 곱하지 않고 시체에 실은 이유는 **시체를 자원으로 둔
        설계와 맞아떨어지기 때문**이다 — 깊은 층의 시체가 좋은 시체고, 관문 주인의
        시체는 특별하다. 층 수를 코드에 안 박았으므로 층 표를 고쳐도 따라온다.
        센 시체에서 일어난 놈은 **조금 더 크다**(raiseScale, 최대 +22%).
      ★★ 한 번 헛디뎠다 — 처음엔 「주인의 최대 체력」만 실었더니 **내리막 고리**가
        생겼다. 소환수가 죽으면 그 약한 주검이 시체가 되고 그것으로 또 약한 놈이
        서고 그놈이 또 죽는다(20층에서 물려받은 체력이 344 여야 할 자리에 **68**).
        **바닥을 그 층에 뒀다**(addCorpse 안에서 `max(pw, floorHp(S.floor))`).
      검증 `node tools/loop_health.mjs 25` (새 검수기 — 25분 굴리며 1분마다 재서
        **무엇이 늘기를 멈추는지**를 본다):
        군대 점유 평균 **48% → 81%** · 「거의 전멸(25%↓)」인 분 **12/25 → 1/25**
        맞고 버티는 횟수가 깊이와 무관하게 3.8~5.2 로 평평해짐(전엔 5.2→0.8)
        cdp_verify ui 오류 0 · netfail 0 · manifestStale 0
      ★ 검수기가 게임을 **그대로 흉내 내지 않으면 게임을 오진한다** — 처음 만든
        loop_health 는 step() 만 돌려서 자동 소환 auto()(main.js 가 부른다)를 빠뜨렸고,
        「2분 만에 얼어붙는다」는 오진을 냈다.

          보스가 죽이는 속도를 **다시 세우는 속도가 못 따라간다**. 다음은 auto() 의
          소환 간격·군세 상한(6~7 고정)을 볼 것. 상한을 올릴지 재소환을 빠르게 할지는
